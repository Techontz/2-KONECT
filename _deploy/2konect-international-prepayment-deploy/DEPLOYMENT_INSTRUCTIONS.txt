2KONECT - INTERNATIONAL PREPAYMENT
DEPLOYMENT INSTRUCTIONS
======================================================================

SERVER : /home/konectsh/domains/api.2konect.shop
API    : https://api.2konect.shop

Nothing below deletes data. There is no migrate:fresh, no db:wipe, no
db:reset, no rollback. Both migrations only ADD.

Set this once so you can copy/paste the rest:

    APP=/home/konectsh/domains/api.2konect.shop
    cd "$APP"


----------------------------------------------------------------------
STEP 1 - BACK UP  (do not skip)
----------------------------------------------------------------------

Timestamped copies of everything this package touches, plus the two
files that carry earlier work.

    STAMP=$(date +%Y%m%d-%H%M%S)
    BK="$APP/_backup-prepayment-$STAMP"
    mkdir -p "$BK"

    # the four runtime files this package replaces
    for f in \
      routes/api.php \
      app/Models/Order.php \
      app/Http/Controllers/Api/Shop/OrderController.php \
      app/Filament/Resources/OrderResource.php
    do
      mkdir -p "$BK/$(dirname $f)"
      cp -p "$APP/$f" "$BK/$f" 2>/dev/null && echo "backed up $f"
    done

    # not replaced, but copied so you can prove the sitemap code is intact
    mkdir -p "$BK/app/Http/Controllers/Api/Shop"
    cp -p "$APP/app/Http/Controllers/Api/Shop/CatalogController.php" \
          "$BK/app/Http/Controllers/Api/Shop/" 2>/dev/null

    ls -R "$BK"

A database backup as well, if your host provides mysqldump:

    mysqldump -u DB_USER -p DB_NAME > "$BK/db-$STAMP.sql"

(Use the DB_USERNAME / DB_DATABASE from your .env. If mysqldump is not
available, take a backup from cPanel before continuing.)


----------------------------------------------------------------------
STEP 2 - CHECK ROUTES/API.PHP BEFORE OVERWRITING IT
----------------------------------------------------------------------

This is the one file that might contain edits made directly on the
server. Look at what you would be replacing:

    diff "$BK/routes/api.php" /path/to/extracted/files/routes/api.php

Expect ONLY additions (lines starting with ">"), namely the
CheckoutPaymentController import and the payment routes.

If the diff shows any line being REMOVED that you recognise as
server-only work, STOP and tell me - do not upload that file.

Upload the ZIP to the server, then:

----------------------------------------------------------------------

----------------------------------------------------------------------

See what will run first:

Expect exactly two:

----------------------------------------------------------------------

Creates two rows, both INACTIVE with no number. Safe to re-run.


----------------------------------------------------------------------
STEP 6 - CLEAR AND REBUILD CACHES
----------------------------------------------------------------------

Order matters: clear everything first, then rebuild.

    php artisan optimize:clear

    php artisan config:cache
    php artisan route:cache
    php artisan view:cache
    php artisan event:cache

route:cache is REQUIRED - the two new endpoints will 404 without it.


----------------------------------------------------------------------
STEP 7 - VERIFY
----------------------------------------------------------------------

7a. Laravel boots

    php artisan about | head -20

7b. No syntax errors in what you uploaded

    php -l routes/api.php
    php -l app/Support/CheckoutPolicy.php
    php -l app/Models/CheckoutPaymentChannel.php
    php -l app/Http/Controllers/Api/Shop/CheckoutPaymentController.php
    php -l app/Http/Controllers/Api/Shop/OrderController.php
    php -l app/Filament/Resources/OrderResource.php

7c. Migrations landed

7d. The payment channel exists and is correctly switched OFF

    php artisan tinker --execute="foreach(App\Models\CheckoutPaymentChannel::orderBy('sort_order')->get() as \$c){echo \$c->code.' active='.(\$c->is_active?'YES':'no').' number='.(\$c->number ?: '(not set)').PHP_EOL;}"

    Expect:
        lipa_namba   active=no  number=(not set)
        mobile_money active=no  number=(not set)

7e. The new routes exist

    php artisan route:list | grep -E "payment-channels|orders/\{reference\}/payment"

7f. THE SITEMAP STILL WORKS  (this is the one to watch)

    php artisan route:list | grep "shop/sitemap"
    curl -s -o /dev/null -w "sitemap: %{http_code}\n" https://api.2konect.shop/api/shop/sitemap
    curl -s -o /dev/null -w "frontend sitemap: %{http_code}\n" https://www.2konect.shop/sitemap.xml

    Both must be 200. If the first is 404, route:cache did not rebuild -
    re-run step 6.

7g. Nothing is throwing

    tail -40 storage/logs/laravel.log

----------------------------------------------------------------------
STEP 9 - SWITCH LIPA NAMBA ON  (the only manual step)
----------------------------------------------------------------------

Until you do this, international checkout has NO payment method and
says so. Nothing is broken - it is waiting for a real number.

    1. Log in to the admin panel
    2. Settings -> Customer Payment
    3. Edit "Lipa Namba"
    4. Number         : your real Lipa Namba
       Merchant name  : 2KONECT
       Instructions   : (edit the wording if you like)
       Active         : ON
    5. Save

Then confirm it is being served:

    curl -s "https://api.2konect.shop/api/shop/payment-channels?import=1"

The number you just typed should appear in "channels".

Leave Mobile Money OFF until a real integration exists.


----------------------------------------------------------------------
STEP 10 - VERIFY THE BUSINESS RULES ON PRODUCTION
----------------------------------------------------------------------

10a. Cash on delivery must be REFUSED on an imported product.
     Replace TOKEN and PRODUCT_ID (any product with availability=import):

    curl -s -X POST https://api.2konect.shop/api/shop/orders \
      -H "Authorization: Bearer TOKEN" \
      -H "Accept: application/json" -H "Content-Type: application/json" \
      -d '{"items":[{"product_id":PRODUCT_ID,"quantity":1}],
           "delivery_address":"Test","customer_phone":"0700000000",
           "payment_method":"cash_on_delivery"}' \
      -w "\nHTTP %{http_code}\n"

    MUST return HTTP 422 and the message
    "Cash on Delivery is not available for products ordered from abroad."

10b. In the storefront, with an imported item in the basket:
        - Cash on Delivery does NOT appear
        - Lipa Namba DOES appear, showing the number you configured
        - the Delivery line reads "Not added yet", not a fee
        - the total is the goods only

10c. Place one real international order and walk it through:
        awaiting_payment
          -> customer submits reference   -> awaiting_verification
          -> admin Verify payment         -> verified
        After verifying, confirm the order still has NO delivery fee.
        Then use Add delivery on the order and confirm the fee appears
        for the customer.

10d. A customer must never be able to set payment_status themselves.
     Sending "payment_status":"verified" with the reference must be
     ignored - the order stays awaiting_verification.


----------------------------------------------------------------------
IF SOMETHING GOES WRONG - ROLLBACK
----------------------------------------------------------------------

Files (safe, immediate):

    cp -p "$BK/routes/api.php"                                   "$APP/routes/api.php"
    cp -p "$BK/app/Models/Order.php"                             "$APP/app/Models/Order.php"
    cp -p "$BK/app/Http/Controllers/Api/Shop/OrderController.php" "$APP/app/Http/Controllers/Api/Shop/OrderController.php"
    cp -p "$BK/app/Filament/Resources/OrderResource.php"          "$APP/app/Filament/Resources/OrderResource.php"
    php artisan optimize:clear && php artisan config:cache && php artisan route:cache

The new files can simply be deleted; nothing that existed before refers
to them.

The database does NOT need rolling back. The new columns are nullable or
defaulted and the old code ignores them, so the previous release runs
unchanged against the migrated schema. Only roll the migrations back if
you have a specific reason to:

    php artisan migrate:rollback --step=2 --force

(That drops checkout_payment_channels and the six payment_* columns. Any
payment references recorded in the meantime would be lost, so take the
database backup from Step 1 first.)


----------------------------------------------------------------------
DO NOT RUN
----------------------------------------------------------------------

    php artisan migrate:fresh      php artisan db:wipe
    php artisan migrate:reset      php artisan db:seed   (with no --class)
    php artisan test               (RefreshDatabase - never on production)
